# ToolForge（占位名）— 跨设备实用工具集 总体设计文档

- 日期：2026-09-23
- 状态：待用户审阅
- 项目根：`d:\toolstest\`
- 名称说明：ToolForge 仅为占位名，非阻塞项，正式名确定后全局替换即可。

## 1. 概述

一套本地优先（local-first）、跨设备可用、公开发布的实用工具集。每个工具是独立的静态 Web 应用：可独立构建、独立发布、独立使用；由一个 PWA 门户提供统一入口。第一期零后端，全部处理在浏览器内完成。

## 2. 背景与用户画像

- 用户身份：学生 + 开发者 + 办公文档处理 + 内容创作（四重身份并存）。
- 高频痛点（每周重复 3 次以上）：图片/文件处理、跨设备倒腾文件、记事/收集/回顾、写代码/处理数据。
- 设备形态：Windows 主力开发机 + 手机 + 平板，多设备均衡使用。
- 发布定位：自用为主，顺便开源。选型跟随自身真实痛点，不为流量妥协。

## 3. 已锁定决策

| 决策项 | 结论 | 理由 |
|---|---|---|
| 使用者范围 | 公开发布，但无账号体系 | 纯静态工具不在服务器存任何用户数据，天然无隐私负担、无合规成本 |
| 部署底座 | 静态托管（GitHub Pages）+ 本机 Windows 开发与局域网使用 | 免费、公开、自带 CDN；本机 `pnpm dev --host` 供手机平板直接访问调试 |
| 技术栈 | Vue 3 + TypeScript + Vite + vite-plugin-pwa，pnpm workspace | 构建快产物小、PWA 生态成熟、中文社区强大、SFC 适合小工具 |
| 同步架构 | 三级火箭渐进式（见 §4） | 每一级不推翻上一级，避免一次性过度设计 |
| 第一期范围 | 门户 + 4 个纯静态工具 | 先验证架构，再引入后端同步 |

## 4. 总体架构：三级火箭

```
第一级（本期）：纯静态工具 + PWA 门户
  任意静态托管全功能运行；手机平板安装即用；零后端零运维。
第二级（后续）：+ 轻量同步服务（单个小后端）
  数据跨设备跟随；存储适配器切换远程实现，工具代码零改动。
第三级（后续）：+ 按需服务端工具
  个别重计算工具自带后端，门户经 manifest 声明式发现，互不拖累。
```

演进原则：升级只做加法；已有工具不改代码。

## 5. 仓库结构

```
d:\toolstest\
├─ portal/                  # 门户：PWA 壳，自动发现并列出所有工具
├─ tools/
│  ├─ image-lab/            # 每个工具 = 一个文件夹 = 一个可独立发布的产物
│  │  ├─ manifest.json      # 工具契约（见 §6）
│  │  ├─ src/
│  │  └─ package.json
│  ├─ pdf-kit/
│  ├─ format-wash/
│  └─ qr-factory/
├─ shared/                  # 可选公共层：主题 CSS 变量、存储适配器（工具可不依赖）
└─ scripts/                 # manifest 校验 + 注册表扫描 + 构建/发布脚本
```

## 6. 工具契约（manifest.json）

门户与工具之间唯一的耦合点。字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | kebab-case，全局唯一，等于文件夹名 |
| `name` | string | 是 | 中文显示名 |
| `description` | string | 是 | 一句话描述（中文） |
| `icon` | string | 是 | 相对 manifest 的图标路径（SVG） |
| `category` | enum | 是 | `media` \| `docs` \| `data` \| `dev` \| `life` \| `fun` |
| `offline` | boolean | 是 | 是否完全离线可用 |
| `entry` | string | 否 | 入口 HTML，默认 `index.html` |

校验规则（`scripts/validate-manifests.mjs`）：缺字段、id 与文件夹名不一致、category 非法、图标文件不存在 → 构建直接失败并指出具体文件。校验脚本本身有单元测试。

## 7. 自动发现机制

构建时 `scripts/` 扫描所有 `tools/*/manifest.json`，汇总生成注册表 `portal/public/tools.json`。门户启动时读取并渲染工具卡片。

**加新工具 = 加一个文件夹 + 重新构建，门户零改动。**

## 8. 独立性铁律

1. `tools/` 之间禁止互相 import；工具间协作只走 URL 参数。
2. `shared/` 是可选依赖，任何工具不依赖它也必须能独立构建运行。
3. 每个工具有独立 `package.json`、可单独 `pnpm build`、产出独立 `dist/`、可单独发布到任意静态托管。
4. 门户对每个工具的全部依赖 = `tools.json` 中的一条记录 + 一个链接。

## 9. 第一期工具规格

### 9.0 portal 门户

- PWA 壳：可安装到主屏、缓存自身资源、离线可打开。
- 工具卡片网格：图标 + 名称 + 描述 + 分类徽章；顶部搜索框按名称/描述过滤。
- 点击卡片新开标签进入工具。
- 部署于站点根路径（base `/`）。

### 9.1 tools/image-lab 图片工作台（分类 media）

- 功能：批量添加图片（选择/拖拽）；压缩（质量滑杆）；格式转换 png/jpeg/webp；尺寸调整（按宽/高/百分比）；文字水印（位置/透明度/字号）；单张下载或 ZIP 打包。
- 核心依赖：浏览器 Canvas API、jszip。
- 验收：10 张约 8MB 照片批量压缩（质量 80）到 2MB 以下且不崩内存；全程零网络请求。

### 9.2 tools/pdf-kit PDF 手术台（分类 docs）

- 功能：合并多个 PDF；拆分（页码范围语法如 `1-3,5`）；旋转单页/全部；删除页面；缩略图拖拽重排；添加页码（位置/起始号/格式）。
- 压缩为尽力而为：pdf-lib 重新保存，不做图像降采样，UI 明示「压缩效果取决于文档」。
- 核心依赖：pdf-lib。
- 验收：80 页文档拆出 3 页耗时 <2s；打开加密 PDF 给出中文错误提示而非白屏。

### 9.3 tools/format-wash 格式洗衣房（分类 data）

- 功能：JSON⇄CSV⇄YAML 互转；Markdown 表格⇄CSV；JSON 格式化/压缩/校验（错误定位到行列）；自动检测输入格式。
- 架构：自研转换核心，经中间表示（先解析为结构化数据再序列化），便于测试与扩展。
- 核心依赖：yaml 库 + 自研核心。
- 验收：转换核心单元测试覆盖典型与边界（空值、含逗号引号换行的转义、Unicode）；非法输入报错含行列号。

### 9.4 tools/qr-factory 二维码工厂（分类 fun）

- 功能：生成（文本/URL，尺寸/纠错级别/前景背景色）；居中嵌 logo（自动留白防误扫）；批量生成（多行文本 → ZIP）；解码（优先 BarcodeDetector API，降级 jsQR；支持摄像头与图片上传）；生成历史存 IndexedDB，可清空。
- 核心依赖：qrcode 库、jsQR、BarcodeDetector（特性检测降级）。
- 验收：离线全功能可用；本工具独立安装 PWA（作为「每工具可独立发布」的示范第二入口）。

## 10. 数据策略与同步演进

- 第一期：所有持久状态存 IndexedDB，读写统一走 `shared/storage` 适配器（接口：`get/set/del/list`，默认 idb 实现）。
- 每个含持久数据的工具提供「导出 JSON / 导入 JSON」，保证无同步服务时数据可携。
- iOS 限制：未添加到主屏的网页可能被系统清理本地数据——导出功能即为兜底，UI 中提示。
- 第二期：适配器新增远程同步实现（换实现不改工具代码）。

## 11. 部署

- GitHub Pages：portal 在根路径 `/`，工具在 `/tools/<id>/`；各工具 vite `base` 相应配置。工具独立部署到自有域名/子路径时只改 base。
- 提供 `.github/workflows/deploy.yml`：推送 main 自动全量构建并发布（公开仓库 Pages 免费）。
- 本机预览：`npx serve dist`；局域网设备访问 `pnpm dev --host`。

## 12. 测试策略

- vitest 单元测试：format-wash 转换核心（重点）、manifest 校验脚本、pdf-kit 页码范围解析、image-lab 尺寸/质量参数计算。
- 构建期校验：manifest 非法则构建失败（见 §6）。
- 第一期不做 E2E，保持轻量。

## 13. 错误处理原则

- 输入校验前置，错误信息一律中文、面向使用者。
- 文件类工具对超大文件给出大小提示；处理逻辑 try/catch，禁止白屏。
- 构建期错误必须失败并指出具体文件（不静默跳过）。

## 14. 非目标（第一期明确不做）

- 无后端、无账号、无云存储、无访问统计。
- 无多语言（仅中文 UI）。
- 无复杂主题系统：亮/暗色跟随系统，用 CSS 变量实现。
- 不做任何服务端文件处理。

## 15. 二期展望（届时另行设计）

轻量同步服务 + QuickDrop 快传、ClipHub 剪贴板同步、语音速记、稍后读。

## 16. 成功标准

1. `pnpm build` 一键产出可部署 `dist`，门户自动列出全部 4 个工具。
2. 每个工具可单独构建、单独部署并独立可用。
3. Lighthouse 判定 PWA 可安装；离线打开门户正常。
4. 单元测试全绿。
5. 手机（Android Chrome / iOS Safari 添加到主屏）实际安装可用。
